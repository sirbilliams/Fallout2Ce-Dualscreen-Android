## Divergence and integration

- Every hook is compiled only under FALLOUT_HD and gated by hd::enabled(),
  except init/exit (lifecycle), and first-run setup which reads the loaded config.
  This deliberately follows the port requirement that enabled=0 is inert;
  Dustlight upstream enables some presentation/hotkeys separately from that flag.
- Emit-only skips clears, CPU blits, refresh callbacks and worldViewRendered.
  World-view clipping/overlay ownership stays unchanged for L3 integration.
  A clipped traversal can therefore be partial at zoom; GPU/pixel equivalence
  and overlay composition still need validation when L3 lands.
- Our tactical see-through compositing has CPU buffer reads/writes absent in
  Dustlight. Emission bypasses those operations and records ordinary objects and
  outlines in original pass order. The tactical visual effect is not encoded in
  the base draw-list contract; L3 must retain CE fallback for those pixels.
- `src/hd/hooks_stub.cc` provides neutral definitions only for hooked symbols.
  enabled() is always false; this lane alone does not record or render HD.
  Remove this source when L1's real implementations land. CMake's temporary
  HD option/target block is marked "L1 replaces this" and covers game + mapper.
- The first-run default-screen behavior remains neutral with stubs. L1 must
  keep enabled() false when [hd] enabled=0, including mapper mode.
